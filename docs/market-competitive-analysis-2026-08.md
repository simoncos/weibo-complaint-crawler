## 执行摘要

### 核心裁决

1. **这个项目当前不是商业舆情平台，也不是线上消费者投诉产品。** `master` 是一套面向微博社区管理中心特定页面的旧式 Python 3.6+、Selenium、MongoDB 研究抓取脚本：登录后枚举特定状态页面、提取举报人／被举报内容／平台处理文本／围观者字段，再写入 MongoDB。仓库没有可验证的线上服务、官方数据授权、客户工作流、告警、仪表盘、权限、删除同步、API、部署、测试或持续运营能力。
2. **历史数据主张不能作为当前产品或市场证据。** [README](../README.md) 写有截至 2018-08-30 的历史数量和一条含可识别字段的样例，但 `master` 没有数据清单、哈希、抓取时间、规则版本、抽样框或复现记录。本轮因此把该数量降为“未经本轮复核的历史 README 陈述”，不把它当语料规模、市场规模、合法性或客户价值。
3. **旧的页面自动化路径同时面临条款、法律、重现性和平台依赖风险。** 微博现行服务协议明确把未经书面许可的高频自动化数据获取列入受限自动化行为 [S01]；微博已有官方 CLI/API 及公开套餐 [S02]。技术上能访问网页，不等于有权持续汇集、画像、再分发或跨境处理。
4. **市场不是空白。** 大中华区已有新浪舆情通、蚁坊、识微、数说声呐、WisersOne、OpView 等舆情／VoC 厂商；欧美已有 Brandwatch、Talkwalker、Meltwater、Brand24、Sprout、Qualtrics、Medallia、Chattermill、Thematic、Zendesk、Trustpilot、ReviewTrackers 等不同层级产品。它们出售的核心是授权数据覆盖、历史回溯、中文或多语语义、分类去重、人工服务、告警、报告、权限、API/导出和持续维护，不只是“抓到文本”。
5. **最低风险的可验证方向，不是立即恢复持续抓取。** 优先级应是：客户自有且有处理依据的数据、官方 API／书面数据合作、监管机构公开聚合或经治理的开放数据、经审批的去标识受控样本、一次性人工抽样、问卷／访谈，以及明确选择“不做持续抓取”。CFPB 自己也声明公开投诉库并非统计样本，叙述不代表机构核实 [S38]；这应成为本项目的最低披露标准，而不是竞争劣势。
6. **建议把 90 天工作定义为“需求与合法数据供给的双重证伪”，而不是产品建设。** 只有同时满足书面授权、伦理／隐私审查、删除纠错链、可重复抽样、人工标注质量、真实使用价值和付费覆盖直接成本，才进入下一阶段。任一红线失败即停止，不转向规避验证码、访问控制、速率限制或平台规则。

### 1.1 `master` 实际做什么

- [weibo.py](../weibo.py) 使用账号密码登录微博，访问固定的社区管理中心筛选页面，以 XPath 枚举案件 URL，再用多进程逐页处理。
- [extract.py](../extract.py) 提取举报账号展示资料、陈述、被举报账号及文本、官方处理文本和围观账号；当页面显示举报人数超过 20 时，只遍历 20 个展示位，但另存页面声明的总数。
- [mongo.py](../mongo.py) 以案件 URL 为键做 MongoDB `replace_one(..., upsert=True)`；没有数据版本、来源哈希、变更历史或删除传播日志。
- [conf.py](../conf.py) 仅有空白账户／Mongo 配置、短等待、重试和并发参数；依赖未锁定，浏览器驱动与 DOM 选择器均属旧实现。
- [README](../README.md) 提供历史下载入口和样例，但样例本身包含可识别的账号、位置、个人描述和自由文本。本报告不复制这些内容。

因此，`master` 能支持的最窄研究表述是：**观察某一历史时期，微博特定治理入口、特定案件类型和状态下，当时页面可见且脚本成功解析的记录。** 它不能支持“微博消费者投诉全量”“中国消费者总体态度”“品牌全网声量”“真实侵害率”或“当前平台治理表现”。

### 1.2 当前没有证据证明的能力

- 没有真实线上服务、SLA、用户、计费、组织权限、租户隔离、审计后台或部署记录。
- 没有微信、小红书、黑猫投诉、12315 或欧美平台连接器；仓库名不能扩张数据边界。
- 没有情绪、主题、实体、去重或跨平台归因模型的 `master` 实现与基准。
- 没有现行平台书面许可、官方 API 覆盖证明、数据处理协议、跨境方案或删除通知机制。
- 没有真实全量数据、完整抽样框、非投诉者对照、人口或客户分母，也没有客户访谈和付费证据。

### 1.3 未合并研究分支是什么、又不是什么

远端研究分支 `28fcda2…` 新增了数据治理、修订协议、基准、验证、人类标注、规则检索和敏感文件扫描等材料，并尝试把“页面显示总人数”和“最多 20 个可见档案”分开建模。这些是有价值的方法原型：来源清单、输入／金标准／关联表分离、失败进入分母、缺失原因、哈希和双人标注均比 `master` 严谨。

但该分支仍明确缺少真实全量数据、可复核清单、历史规则快照、正式人工标注和数据处理审批。故本报告只把它作为 E2 证据，不能把其计划、合成测试或脚手架描述成已上线能力、已验证模型或已完成研究。

## 三、市场结构与地区差异

### 3.1 大中华区不是一个同质数据市场

**中国大陆。** 微博当前协议限制未经书面许可的自动化获取 [S01]，同时开放平台已有授权 CLI/API 与按月套餐 [S02]；旧 Selenium 路径因此既不是稳定供给，也不是护城河。微博隐私政策列出账号、内容、设备等个人信息处理与权利机制 [S03]。黑猫投诉的隐私政策显示，投诉流程可能涉及订单、合同、金额、联系方式等高敏感语境数据，并会在处理目的下向被投诉企业提供必要信息 [S04]；游客可浏览部分页面，不代表第三方可重建原始投诉库。

小红书公开服务商接口要求商家／小程序授权 [S05]，本轮未找到可供一般第三方研究全站笔记和评论的授权接口；腾讯隐私政策又明确用户可控制被发现和内容可见范围 [S06]。所以小红书与微信只能优先使用品牌自有数据、明确授权合作或经伦理审查的受控样本。“本轮未找到”不是断言接口绝对不存在，而是采购或研究前必须由平台书面确认。

PIPL 对已合法公开个人信息仍要求“合理范围”，个人明确拒绝或处理对权益有重大影响时还有更高约束 [S07]；《网络数据安全管理条例》把分类分级、个人权利和安全责任带入持续数据处理 [S08]，跨境规则还会因数据类型、规模和路径触发评估、标准合同或其他条件 [S09]。民法典人格权规则要求对未经裁定的指控保持事实／陈述区分，并提供核实、纠错和停止传播机制 [S10]。

监管体系也提供更低风险替代。12315 投诉公示规则明确，投诉陈述和自愿调解结果不等于处罚、失信或事实裁定 [S11]。这说明“聚合趋势＋口径说明”比复制个人投诉原文更适合早期验证。

**香港。** PCPD 与其他监管机构指出，即使社媒资料公开可见，获准抓取仍须守法律和合同，并建议平台提供合规 API [S12]；其公共领域指引进一步说明，公共域个人资料并没有一般性豁免，再利用仍受原收集目的、订明同意及其他 DPP 要求约束；研究／统计等法定豁免若被主张，也须逐项满足其具体条件，不能自动适用 [S13]。香港消委会的职责是调停而非裁决，公开投诉页面主要提供流程和汇总信息 [S14]；data.gov.hk 另有投诉统计开放数据 [S15]，更适合宏观研究，不应反向推导个人案件。

**台湾。** 现行个资法对非公務机关收集和利用要求特定目的、法定基础、必要性、安全与停止利用机制；页面显示 2025 年修法部分条文尚未确定施行日 [S16]，本报告不把未生效条文当现行要求。行政院线上申诉是身份核验、转交与分级处理流程，所提交资料限于处理目的 [S17]，不是公共研究语料源。

### 3.2 欧美市场更强调分层采购，而非一个“舆情”品类

欧美／全球供应侧可分为：

1. **跨网社交与媒体聆听**：Brandwatch、Talkwalker、Meltwater、Brand24、Sprout；
2. **VoC 与非结构化反馈分析**：Qualtrics、Medallia、Chattermill、Thematic；
3. **客服与评论工作流**：Zendesk、Trustpilot、ReviewTrackers；
4. **平台官方 API／研究访问**：X、Reddit、Google/YouTube、Meta、TikTok；
5. **监管开放数据与研究数据集**：CFPB、FTC、CPSC、FCA、DSA 数据库、Yelp、Amazon Reviews；
6. **不用持续抓取的研究替代**：人工编码、问卷、访谈、日记研究和事件触发式桌面研究。

成熟产品的价格不在同一层级。公开页显示，Brand24 年付折算从每月 $199 起 [S28]，Sprout 的基础席位计划公开定价但 Listening 需另购 [S29]，Thematic Foundation 为每年 $25,000 且有反馈量／数据集上限 [S34]，Trustpilot 从免费到每域名每月 $99、$319、$799，再到询价 Enterprise [S36]。Brandwatch、Talkwalker、Meltwater、Qualtrics、Medallia 和 ReviewTrackers 等多为演示／询价 [S24][S25][S27][S31][S32][S37]。这些数字只证明相邻预算类别存在；不证明客户会为本项目付费。

### 3.3 市场规模边界

本轮**不提供 TAM/SAM/SOM 数字**，原因是缺少可审计的目标客户定义、采购单位、成交价、渗透率、流失、替代成本和合法数据供给。平台用户数、帖子数、投诉数、厂商“覆盖量”和仓库历史记录数都不能直接变成可服务市场。90 天验证应先回答“谁为哪个决策付费”和“可否合法持续供给”，再决定是否值得做自下而上的市场测算。

## 五、评估维度与采购真成本

### 5.1 数据合法性与来源契约

每个来源必须有一行“来源合同卡”：控制者、获取依据、允许用途、禁止用途、账号／令牌、地域、字段、历史深度、配额、缓存期限、再分发、模型训练、删除通知、权利请求、跨境、分包商、终止和退出导出。没有书面许可时，“公开可见”只能支持有限人工观察，不能自动升级为持续采集许可。

### 5.2 覆盖与代表性

旧脚本至少受以下机制影响：只看微博单一入口、固定案件类型与状态；登录可见性；平台审核与裁决；自选择举报；页面排序；超过 20 人的展示截断；昵称和账号变化；删帖／改可见；组织账号、营销账号和个人账号混合。社媒研究已系统总结来源、收集、处理和推断偏差 [S51]，因此项目只能估计“在定义清楚的观察框内可见的记录”，不能推断总体消费者或真实发生率。

即使改用官方 API，也要建立人工参考框，在多个时段估计覆盖率与关键群组差异；API 成功率只说明请求成功，不说明样本代表总体。

### 5.3 质量、时效与复现

最低可复现单元应包含：来源与条款版本、获取时间、请求或页面标识、原始对象哈希、解析器版本、字段缺失原因、删除／编辑状态、分类体系版本、人工标注版本和导出版本。社媒数据会因删除与元数据漂移随时间衰减 [S52]；所以“每次重跑得到完全相同原文”并不现实。合理目标是：不可变受控快照哈希一致；可变源产生版本化差异；删除得到传播而非被“修复”回数据库。

时效也不是越快越好。对身份级指控，高速自动告警会放大诽谤和误认风险；必须先做来源可信度、事实／指控分栏、实体消歧与人工确认。监管数据的月／季／半年节奏可能已足够支持政策或行业趋势 JTBD。

### 5.4 分类、去重、实体解析与中文语境

中文投诉和舆情至少要处理：简繁转换、粤语／台湾用语、谐音和变体、反讽、转述与引用、品牌简称、门店／集团／产品层级、同名实体、截图文字、多模态、话题动员、重复转发、多个举报人对同一对象、同一用户多次陈述，以及平台“举报／投诉／辟谣／裁决”语义差异。

不能只报告一个总体准确率。分类应按关键类别给出召回；去重与实体解析优先高精度，避免把不同主体错误合并；重要结论保留证据链与人工复核。任何模型输出都要区分：原始陈述、平台处理、研究编码、模型推断和法律事实。

### 5.5 人工复核、导出与审计

- 身份级指控、敏感类别、低置信分类、跨实体合并和公开结论必须人工复核。
- 对外默认只导出去标识聚合；不导出账号、个人简介、联系方式、可搜索原句或稳定个人标识。
- 导出应带数据字典、口径、样本范围、缺失、版本、错误率、偏差限制和删除截止时间。
- 每次访问与导出记录操作者、目的、字段、行数、时间和批准人；定期验证删除／拒绝／纠错传播。

AoIR 的互联网研究伦理指南强调，公开性不能代替情境风险判断，研究者须考虑可识别性、可搜索引文、脆弱群体、归档与销毁 [S53]。这正是本项目处理投诉文本时应采用的底线。

### 5.6 价格与 TCO

真实 TCO 至少包括：平台/API/供应商许可、历史回溯、关键词／提及量、席位、地域与语言、存储、OCR/模型、人工编码与复核、分类体系维护、误报处理、法律与伦理审查、安全、删除同步、审计、客服、迁移与退出导出。公开套餐只是下限；询价产品尤其要索取来源级覆盖、DPA、子处理者、删除 SLA、数据驻留、审计权和终止后数据处置。

### 5.7 平台锁定与迁移成本

平台可改变端点、价格、配额、字段、审核、研究资格和可见性。供应商还可能使用不可导出的查询语言、主题模型、历史档案或实体图谱。降低锁定的办法是保存自有 taxonomy、数据字典、标注金标准、来源合同卡、供应商无关的规范化 schema 和可删除 ID 映射；只存有权保留的原始数据，不以“防止丢失”为由绕过删除要求。

## 六、护城河与反护城河

### 6.1 可能形成的护城河

1. **可审计的中文平台治理研究方法**：把页面展示上限、实际人数、删除、缺失、规则版本和人工金标准显式建模。
2. **中文语境与跨地区 taxonomy**：大陆、香港、台湾的投诉制度、繁简、粤语、实体层级与平台语义可以形成方法资产。
3. **治理优先的证据链**：授权、血缘、删除、纠错、事实／指控分栏和审计导出如果真正落地，会比一次性脚本更有价值。
4. **受控样本上的人工—模型协作**：不是追求“全量”，而是证明在窄问题上比纯人工更快且不降质量。

### 6.2 更强的反护城河

1. 数据入口和账号不属于项目；平台可随时改变 DOM、条款、API、价格或研究资格。
2. 旧 Selenium/XPath/Mongo 实现容易复制，本身没有数据权、分发、客户工作流或独有算法。
3. 历史自由文本随删除、编辑、规则变化和样本选择而衰减，越“全量”越增加治理负担。
4. 成熟厂商已有授权数据、跨网覆盖、人工服务、告警、报告、权限、API 和销售渠道。
5. 监管开放数据、官方 API、第一方客服、人工编码和“不持续采集”都可能以更低风险完成同一 JTBD。

**裁决：**若有护城河，只可能来自“合法数据关系＋经验证的中文方法＋可审计工作流＋真实客户学习”，不会来自旧数据量或抓取技巧。

## 七、法律、平台、伦理与内容治理

### 7.1 条件式法律分析

- **PIPL／大陆。** 合法公开信息仍受合理范围、拒绝、重大影响、敏感信息、自动化决策、跨境、删除和事前影响评估约束 [S07][S09]。具体适用取决于处理者、目的、主体、服务器、接收方和规模，须由当地法律顾问裁定。
- **GDPR／欧洲连接点。** 若项目处理欧盟境内个人行为监测或其他受 GDPR 规制的活动，仍需合法基础、目的限制、最小化、透明、准确、保留限制、安全、权利响应；研究目的不是当然豁免，Art. 89 保障须与风险相称 [S55]。化名数据仍可能是个人数据；只有不可逆匿名才脱离个人数据范围。
- **香港 PDPO。** 公开域资料仍受收集目的、适度、准确、保留、安全、用途限制和访问／更正规则影响；研究／统计等法定豁免若适用，也须满足具体条件，不能因项目自称“研究”而自动豁免 [S12][S13]。
- **台湾个资法。** 合法公开或一般可得来源可能构成部分收集依据，但不取消特定目的、比例、安全、停止利用／删除和跨境限制；采购前须核对 2025 修法的实际施行文本 [S16]。

### 7.2 平台条款与授权

微博协议是当前旧路径最直接的否决证据 [S01]。其他平台也把正式访问限定在授权商户、合资格研究者、凭证、配额、地区、用途和删除义务内 [S43][S44][S45][S46][S47]。因此：robots 允许、页面可见、登录成功或请求返回 200 均不能单独证明获得采集、再利用、模型训练或商业再分发许可。

### 7.3 诽谤、名誉与投诉内容治理

投诉是当事人陈述，平台处理是平台程序结果，监管处罚和法院认定又是不同证据层。12315 官方规则明确否认把投诉陈述／自愿调解当作处罚、失信或事实认定 [S11]。项目必须：

- 使用“有人陈述／平台显示／研究编码”而不是确定性归责措辞；
- 不做公开的个人或小微主体风险分数、黑名单和可搜索原文；
- 对企业实体也保留同名消歧、时间、来源和纠错入口；
- 在身份级输出前要求人工核实和双来源；若无法核实则只做聚合；
- 接到删除、反对、纠错或平台下架通知时停止继续传播并更新派生物；
- 把 PII 泄漏、错误实体合并、未核实指控自动发布列为严重事件。

### 7.4 研究伦理

伦理审查贯穿问题定义、样本、收集、标注、模型、展示、归档和销毁，而不是发表前一次打勾 [S53]。公开内容仍可能来自脆弱主体、敏感纠纷或低预期传播情境；逐字引文可能被搜索反向识别。本项目应默认最小字段、不可逆聚合、受限访问、短保留、禁止外部模型处理原文，并在实际数据进入项目前完成伦理决定与退出机制。

## 九、90 天最低风险验证

以下均为**建议的决策门槛**，不是市场事实或现有成绩。目标是尽快证伪，不是凑指标继续建设。

### 第 0 阶段：第 1–15 天，先过授权与需求门

**动作**

- 为每个候选数据源取得书面许可、明确官方 API 条款或选择官方聚合／客户第一方数据；确认社区管理中心是否在微博授权范围内。
- 完成数据流图、PIPIA/DPIA 适用判断、伦理决定、跨境与外部模型禁用判断、删除／纠错／事故流程。
- 访谈至少 15 名合格用户，覆盖研究、品牌／客服、权益或监管分析三类角色；要求他们展示去标识的现有工作流、决策和替代成本。

**进入门槛**

- 至少 5 名受访者复现同一个高优先 JTBD；至少 3 名愿提供受控影子流程；其中至少 2 名已经签署付费试点协议且首笔试点费实际到账。口头意向、LOI 或“愿意考虑”不计入。
- 至少 1 个来源具备书面授权、明确删除机制和可审计的用途范围；仅网页可见不算。

**停止条件**

- 无书面许可、必须规避平台控制、法律／伦理审查不通过；
- 少于 2 个已签约且首笔费用到账的设计伙伴，或问题只被描述为“数据有趣”而无真实决策；
- 任何方案依赖保存或公开身份级投诉原文。

### 第 1 阶段：第 16–45 天，受控样本与金标准

**动作**

- 只用合成数据或授权／去标识样本；分层抽样至少 300 条，按来源、时间、类别和缺失状态记录抽样概率。
- 对所有关键标签做双人独立编码和分歧裁决；版本化 taxonomy、指南和金标准。
- 构建来源清单、对象哈希、解析版本、缺失原因、删除状态和导出审计。

**进入门槛**

- Krippendorff’s α ≥ 0.75；关键分类 macro-F1 ≥ 0.80 且各关键类召回 ≥ 0.75；去重 F1 ≥ 0.95；实体解析精度 ≥ 0.95。
- 来源／血缘／版本覆盖 100%；人工检查导出中的可识别个人资料泄漏为 0。

**停止条件**

- 无法形成稳定的人工金标准或清楚的失败分母；
- 任一可识别投诉、账号或可搜索原句进入外部报告；
- 质量只在随机切分上成立，跨时间／来源显著失效且无法说明。

### 第 2 阶段：第 46–75 天，覆盖、删除与可重复性

**动作**

- 在三个不同时段，将官方 API／授权源与授权人工参考框比较；报告捕获率、缺失、编辑、删除和关键群组差异。
- 对不可变样本验证哈希一致；对可变源输出版本化 diff；进行删除／反对／纠错演练。

**进入门槛**

- 覆盖率 95% 置信区间下界 ≥ 0.80，且关键群组捕获率差距不超过 15 个百分点。若群组差距超标，只能先缩窄目标人群、来源或用途并重新计算；客户书面接受不能豁免该门槛。
- 删除、拒绝和纠错在 72 小时内向索引、缓存、派生物和导出清单传播，演练成功率 100%。

**停止条件**

- 连续两轮覆盖不达标、无法计算分母，或缩窄用途后已不能完成原 JTBD；
- 一次删除传播失败、账号／接口变化迫使非授权采集，或数据许可不允许目标用途。

### 第 3 阶段：第 76–90 天，影子流程和付费真实性

**动作**

- 第 0 阶段已签约且付款的两家设计伙伴各跑一次完整影子流程；同一输入下，与其现有人工／供应商流程盲比。
- 记录分析工时、复核工时、误报处理、许可、模型、存储、法律／安全和客户支持的全成本。

**进入下一阶段门槛**

- 分析总工时较人工基线下降 ≥ 30%，盲审质量不下降；每家至少有 1 个输出实际支持一项可记录决策。
- 付费覆盖全部直接 API／许可／人工复核成本，并有重复使用或续费意向。

**停止条件**

- 没有重复使用意向、直接成本高于付费、客户只想购买原始个人数据；
- 出现未人工核实的身份级输出、诽谤风险、PII 泄漏或权利请求积压。

## 不利因素应对提案

> 阶段状态：第二阶段方案设计，核验日 2026-08-10。以下均为**尚未实施**的提案、门槛与停止条件，不代表 `master`、远端研究分支或任何线上系统已经具备相应能力。
>
> 证据边界：本阶段没有发现必须补充的新事实缺口，未新增定向搜索或来源；新增来源数为 **0**。本章只复用第一阶段已经闭环的仓库证据及 [S01]–[S56]，不把厂商自述、套餐、历史记录数或模型指标改写成需求、合法性或客户价值。

### 1. 决策原则与评级

1. **先证明数据权，再证明技术。** 没有书面授权、明确官方 API 范围或客户对第一方数据的有效处理依据时，持续采集保持 no-go；页面可见、登录成功、robots 未禁止或请求返回成功都不构成授权 [S01][S12]。
2. **先证明可删除，再允许入库。** 无法把删除、更正、反对和平台下架传播到索引、缓存、派生物及导出时，不接收真实用户数据。
3. **先证明问题和付费，再扩展来源。** 厂商报价只说明相邻预算类别存在 [S23][S24][S25][S27][S28][S34][S36]；口头兴趣、LOI、帖子数、投诉量和模型分数都不算付款或成效。
4. **研究例外一律条件化。** PIPL、GDPR、香港 PDPO、台湾个资法及研究／统计例外是否适用，取决于实际主体、地点、目的、数据流、保障与法定条件 [S07][S09][S12][S13][S16][S55]；不得由项目自行宣布豁免。
5. **只允许三类验证数据。** 官方公开聚合资料、明确授权的数据、合成或受控样本。不得登录私人账号、运行真实投诉抓取、规避验证码／配额／访问控制，或把投诉原文送入外部模型。

评级定义：影响分为“致命／高／中”；概率／当前性分为“已存在／高／中／未知”；可控性分为“高／中／低”。优先级 P0 是进入任何真实数据工作前必须处理，P1 是试点前必须处理，P2 是规模化前处理。策略使用“阻断、缓解、接受、no-go”四种；“接受”只适用于已量化、已披露且不伤害个人的残余限制。

### 3. 可执行提案（12 项，均未实施）

资源级别：S 为不超过约 10 人日且不采购付费数据；M 为约 10–30 人日并可能需要有限法律／安全／采购支持；L 为超过 30 人日、正式许可或持续基础设施投入。人日仅用于方案量级比较，不是报价。

#### P01：建立“产品边界与证据声明登记册”

- **对应根因：**R01、R02。仓库名称、`master`、远端研究分支、合成测试和拟议能力容易被混写。
- **首选方案：**由研究负责人维护单一登记册，每项能力标记 `master 已实现`、`远端分支原型`、`合成测试通过`、`真实数据已验证`、`仅提案` 五种状态；所有对外材料从登记册生成。
- **备选与取舍：**备选是只保留静态免责声明，成本低但无法阻止后续文档漂移；不建议把分支合并当作“能力完成”的代理。
- **30／60／90 天：**30 天内定义词典和当前基线；60 天对报告、演示、销售与研究结论做逐项追踪；90 天由独立审阅者抽查每条声明的提交、测试、数据和批准证据。
- **Owner／能力／依赖：**Owner 为研究负责人；需要 Git、研究方法和产品写作能力；依赖当前仓库与分支只读证据。
- **资源级别：**S。
- **地区差异：**大中华区材料须区分微博治理研究、消费者投诉与舆情；欧美材料须区分 social listening、VoC、客服分析和研究数据访问。
- **副作用：**短期会减少可宣传功能，并暴露大量“未知／未实现”。
- **最低成本验证：**抽取现有报告 20 条能力陈述，让两名审阅者独立归类并核对证据。
- **量化阈值：**100% 声明有状态和证据链接；审阅者一致率 ≥ 0.90；能力误归属为 0。
- **停止／转向：**若负责人不接受公开标注限制，停止任何对外产品化；转为内部研究备忘录。

#### P02：建立数据权利与来源合同卡

- **对应根因：**R03、R04、R05、R26。目标入口现状、官方 API 范围、再分发和退出条件均未知。
- **首选方案：**对每个候选源建立合同卡，记录控制者、书面授权、用途、字段、地域、历史深度、配额、缓存、模型训练、再分发、删除通知、跨境、分包商、终止和退出导出；只接受官方 API、书面合作、客户第一方数据或官方聚合。
- **备选与取舍：**若平台不提供目标入口授权，转向 12315／香港消委会等官方聚合 [S11][S15]、客户第一方 VoC 或一次性人工研究；牺牲实时和个案覆盖，换取明确边界。
- **30／60／90 天：**30 天列出最多 3 个候选来源并完成未知项；60 天取得平台／供应商书面答复或把来源判为 no-go；90 天只为通过合同卡的一个来源设计受控试点。
- **Owner／能力／依赖：**Owner 为数据权利负责人；需要平台合同、采购、隐私与 API 文档能力；依赖法务审核和明确 JTBD。
- **资源级别：**M；正式数据许可可能升级为 L，但不得预先采购。
- **地区差异：**大陆平台优先平台书面授权与本地处理；香港／台湾分别核对目的和跨境条件；欧美平台按研究资格、DPA、删除和 DSAR 条款逐项核对 [S43][S45][S46][S47]。
- **副作用：**可能判定社区管理中心和多个社媒源永久不可用，降低“全网”叙事。
- **最低成本验证：**只向平台／供应商发送一页用途与字段问卷，不提交账号、不上传数据、不调用真实接口。
- **量化阈值：**试点来源 100% 必填项有书面答案；授权范围、删除、再分发和终止四项不得为“推定”；未知关键项为 0。
- **停止／转向：**第 60 天仍无书面授权，持续采集永久 no-go；转官方聚合、客户第一方数据、人工抽样或“不持续抓取”。

#### P03：设立逐数据流法律、伦理与处理批准门

- **对应根因：**R11、R14、R24。没有角色、法律基础、伦理决定或跨境数据流图。
- **首选方案：**在任何真实数据进入前绘制字段级数据流，条件化评估 PIPL、GDPR、香港 PDPO、台湾个资法、人格权／诽谤、研究伦理、跨境和外部处理者；批准必须绑定用途、来源、字段、保留期、接收方、模型和输入哈希。
- **备选与取舍：**无法取得正式审批时，只用合成数据或不可逆官方聚合；可以继续方法开发，但不能产生个体或企业结论。
- **30／60／90 天：**30 天完成角色与数据流草图；60 天取得法律、隐私、安全和伦理书面结论；90 天仅对批准范围做一次受控审计，不把“研究”当自动例外。
- **Owner／能力／依赖：**Owner 为隐私／法律负责人；需要当地法律、研究伦理、安全架构；依赖 P02 合同卡和 P07 字段／保留设计。
- **资源级别：**M；跨四法域正式意见可能为 L。
- **地区差异：**大陆重点是合理范围、敏感信息、PIPIA 与跨境 [S07][S09]；香港研究／统计例外须逐条件成立 [S12][S13]；台湾须核实施行文本 [S16]；欧洲须明确 Art. 5/6/14/17/21/89 及成员国条件 [S55]。
- **副作用：**审批可能缩窄字段、地区、用途和保留，且不同法域结果不能复用。
- **最低成本验证：**用纯合成数据走完一次审批表和拒绝场景桌面演练。
- **量化阈值：**100% 数据流节点有控制者／处理者、目的、依据、地区和保留；P0 法律问题为 0；所有批准有到期日和撤回路径。
- **停止／转向：**任一主管角色拒绝、结论冲突未解决或要求规避平台控制时停止；转不可逆聚合或纯方法研究。

#### P04：建立可复现受控数据包与证据清单

- **对应根因：**R06、R07、R09、R17。正式数据、哈希、规则版本和可重跑环境缺失。
- **首选方案：**先用合成夹具形成规范：数据清单、来源与授权 ID、对象哈希、获取／生成时间、schema、解析器、规则快照及生效期、依赖锁、缺失／删除状态和批准 ID；不可变输入按哈希重跑，可变源只比较版本化 diff。
- **备选与取舍：**若历史真实数据权利无法证明，只发布合成可复现包和方法，不恢复或传播旧原文；牺牲经验结论，保留工具可验证性。
- **30／60／90 天：**30 天冻结合成 schema 和清单模板；60 天由两名操作者独立重建同一合成结果；90 天仅在 G02–G05 通过后把一个授权受控样本纳入相同流程。
- **Owner／能力／依赖：**Owner 为数据工程／研究方法负责人；需要版本控制、哈希、环境锁定和规则研究；依赖 P02、P03、P08。
- **资源级别：**M。
- **地区差异：**大中华区须记录平台规则与案件时间对应、简繁和地区字段；欧美官方／研究 API 须记录资格、端点、项目配额和协议版本，不能把控制台配置当持续行为证明。
- **副作用：**增加每次数据变更的文档负担；删除后无法承诺字节级历史复现。
- **最低成本验证：**对现有合成夹具做两次独立重建，不接触真实记录。
- **量化阈值：**清单字段覆盖 100%；不可变输入与输出哈希一致；两名操作者重建成功率 100%；未验证历史实证声明为 0。
- **停止／转向：**无法证明来源或规则生效期时删除相应经验主张；只保留合成工具测试。

#### P05：定义 estimand、抽样框与代表性门

- **对应根因：**R08、R17、R18。平台入口、自选择、截断、删除和地区差异使样本无法自动代表总体。
- **首选方案：**每个问题先写目标总体、观察总体、抽样单位、纳入／排除、时间窗、平台状态、已知截断和可比较群组；在授权人工参考框上估计捕获率、缺失和群组差异。
- **备选与取舍：**若没有抽样框，就把结论降为“描述受控样本”，或改用概率样本监管数据、问卷和访谈 [S40][S54]；不输出总体比例。
- **30／60／90 天：**30 天写一个窄 JTBD 的 estimand；60 天只用合成或授权样本演练分层与权重；90 天在三个时段比较授权源和人工参考框。
- **Owner／能力／依赖：**Owner 为方法／统计负责人；需要抽样、缺失、置信区间和平台语境；依赖 P02 授权、P04 清单、P06 金标。
- **资源级别：**M。
- **地区差异：**大中华区按微博／小红书／微信私域、投诉制度和简繁语境分层，不合并为“中国社媒”；欧美按平台 API、监管行业和国家分别报告。
- **副作用：**样本和结论会显著缩窄，可能无法满足“全网声量”诉求。
- **最低成本验证：**用 300 条合成分层记录和模拟缺失验证计算与报告模板；真实数据仅在授权后使用。
- **量化阈值：**授权试点的捕获率 95% CI 下界 ≥ 0.80；关键群组差距 ≤ 15 个百分点；所有分母与缺失原因覆盖 100%。客户书面接受不能豁免阈值。
- **停止／转向：**连续两轮不达标时先缩窄人群／用途并重算；缩窄后不能完成原 JTBD 则停止总体推断，转定性研究或官方聚合。

#### P06：建立地区化 taxonomy、人工金标与模型质量门

- **对应根因：**R07、R13、R18、R22。中文语境、同名实体和事实层混淆会产生高伤害错误。
- **首选方案：**把原始陈述、平台处理、研究编码、模型推断和法律事实分层；按大陆／香港／台湾及目标欧美语种建立指南，双人独立标注、分歧裁决、按关键类与群组报告。
- **备选与取舍：**若自动化达不到门槛，保留人工编码或只自动做低风险检索／聚类；牺牲吞吐量，避免身份级误判。
- **30／60／90 天：**30 天用合成例定义 taxonomy 和禁用输出；60 天在至少 300 条授权／受控样本上双标；90 天才评估候选模型，且真实用户数据模型实验须先过 G02–G07。
- **Owner／能力／依赖：**Owner 为 NLP／研究方法负责人；需要中文语言、地方语境、标注运营、实体解析和评估；依赖 P03、P05、P07。
- **资源级别：**M 至 L，主要成本是合格人工复核。
- **地区差异：**大陆关注平台治理与品牌层级；香港需要粤语／繁体和 PDPO 情境；台湾需要繁体与在地申诉语义；欧美模型不能直接充当中文基线。
- **副作用：**高质量双标降低速度；稀有高风险类别需要更多人工样本。
- **最低成本验证：**先对合成、改写且不可回溯个人的案例做盲标和错误分类演练。
- **量化阈值：**Krippendorff’s α ≥ 0.75；macro-F1 ≥ 0.80；各关键类召回 ≥ 0.75；去重 F1 ≥ 0.95；实体解析精度 ≥ 0.95；未经人工复核的身份级输出为 0。
- **停止／转向：**任一关键类或地区连续两轮不达标，则禁止该地区／类别自动化；转人工编码、只做聚合或停止该 JTBD。

#### P07：执行字段最小化、保留与残余识别风险控制

- **对应根因：**R12、R15。投诉语境敏感，移除直接标识仍可能被上下文重识别。
- **首选方案：**默认字段拒绝列表，业务目的逐字段批准；原始层与分析层隔离，加密、最小权限、短保留、不可逆聚合、外部模型禁投、导出禁止可搜索原句；发布前做残余识别风险审查。
- **备选与取舍：**若无法证明字段必要性，只保留官方聚合或由客户在其环境内计算；降低分析细度，换取数据不出域。
- **30／60／90 天：**30 天完成字段白名单和保留表；60 天用合成敏感字段测试拒绝、掩码和到期删除；90 天仅在批准后审计一个受控样本的全生命周期。
- **Owner／能力／依赖：**Owner 为隐私／安全负责人；需要数据分类、访问控制、匿名化风险和安全测试；依赖 P03、P08、P12。
- **资源级别：**M。
- **地区差异：**大陆要额外识别敏感个人信息与跨境；香港／台湾依目的和必要性缩减；欧洲化名仍可能是个人数据，不能标为匿名 [S55]。
- **副作用：**实体链接、纵向研究和错误诊断能力下降；不可逆聚合会限制后续重算。
- **最低成本验证：**向合成数据注入虚构联系方式和唯一组合，验证入口、日志、导出、备份全部拒绝或按策略处理。
- **量化阈值：**实际联系方式泄漏为 0；字段目的／保留／批准覆盖 100%；到期删除成功率 100%；外部模型原文调用为 0；任何“匿名”声明须有书面风险评估。
- **停止／转向：**一次 PII 泄漏、无法执行保留期或残余风险高于批准标准即停止真实数据；转客户本地计算或不可逆聚合。

#### P08：建立删除、更正、反对与审计传播链

- **对应根因：**R10、R17。现有 Mongo upsert 没有版本、权利请求或派生物传播。
- **首选方案：**为授权对象使用可删除内部 ID 和来源状态；建立从原始层到索引、缓存、特征、模型输入、报告、导出清单的血缘；请求到达后 fail-closed，记录批准、操作者、时间和结果。
- **备选与取舍：**无法可靠删除时不保存原始数据，只做会话内计算或官方聚合；历史重跑能力会降低。
- **30／60／90 天：**30 天画出删除图和 SLA；60 天用合成 ID 做删除／更正／拒绝／平台下架四类演练；90 天在批准的受控样本上由独立审计者复演。
- **Owner／能力／依赖：**Owner 为数据治理／运维负责人；需要血缘、存储、缓存、导出和事故响应；依赖 P04、P07、P12。
- **资源级别：**M 至 L。
- **地区差异：**各平台删除义务依具体协议和环境而定，不能把 Meta、Reddit 或其他平台的规则互相泛化 [S43][S46]；各法域响应时限由法律意见确定。
- **副作用：**版本与删除墓碑增加存储和操作复杂度；某些历史统计会随删除改变。
- **最低成本验证：**只用 100 个合成对象及 5 类派生物做定时演练。
- **量化阈值：**72 小时内传播成功率 100%；所有派生物血缘覆盖 100%；删除后不可由普通备份恢复；一次失败即 P0 事故。
- **停止／转向：**任一真实请求传播失败、平台要求停止或血缘出现未知分支即停用来源；不得复制到新库规避删除。

#### P09：设计授权来源适配层与 fail-closed 漂移控制

- **对应根因：**R04、R05、R16、R26。单平台 DOM、API、配额和供应商锁定会造成静默故障。
- **首选方案：**仅为通过 P02 的官方 API／数据合作设计标准化输入接口；schema、配额、401/403/429、删除通知和协议版本变化一律停止并人工复核。保存自有 schema、taxonomy、金标和退出导出，不保存无权保留的原文。
- **备选与取舍：**如果没有授权 API，使用官方聚合下载、客户侧导出或一次性人工研究；不以浏览器自动化、账号轮换、代理或速率规避补位。
- **30／60／90 天：**30 天只写接口契约和模拟器；60 天用 mock 响应测试配额／权限／schema 漂移；90 天仅在 G02–G08 全过后评估一个授权 sandbox，不运行生产采集。
- **Owner／能力／依赖：**Owner 为数据平台负责人；需要 API 契约、可观测性、配额和安全；依赖 P02、P04、P08。
- **资源级别：**M；多来源适配为 L，当前不批准。
- **地区差异：**大中华区多为平台／商家授权和封闭生态；欧美研究 API 资格、项目配额和删除条款更文档化，但仍会变化 [S42][S43][S44][S45][S47]。
- **副作用：**fail-closed 会降低可用性；标准 schema 可能丢失平台特有字段。
- **最低成本验证：**本地合成 mock 注入权限失效、配额耗尽、字段删除、类型变化和删除通知，不连接真实平台。
- **量化阈值：**所有模拟 401/403/429/schema 不兼容均 100% 停止；静默继续为 0；协议外重试和规避行为为 0；事件日志覆盖 100%。
- **停止／转向：**授权撤回、条款冲突、关键 schema 无法映射或退出导出失败时停用适配器；转人工／聚合源。

#### P10：用签约付款和影子决策验证真实需求

- **对应根因：**R19。没有买方、预算、付费意愿、复用和成效证据。
- **首选方案：**访谈研究、品牌／客服、权益分析三类用户，要求展示经同意且去敏的现有流程；只为一个窄 JTBD 提供合成或授权受控影子分析，并以签约且首款到账确认需求。
- **备选与取舍：**若没有付费伙伴，提供一次性方法咨询或停止；不以免费试用、问卷“兴趣”或厂商市场规模填补需求证据。
- **30／60／90 天：**30 天完成 ≥15 次合格访谈；60 天取得 ≥2 份付费试点协议且首笔费用到账；90 天两家各完成一次与现有人工／供应商的盲比。
- **Owner／能力／依赖：**Owner 为产品研究／商业负责人；需要访谈、采购流程、价值测量和合同能力；依赖 P01–P08 通过相应门禁。
- **资源级别：**M。
- **地区差异：**大中华区分别验证品牌舆情、投诉协同和平台治理研究，不假设同一买方；欧美分别验证 social listening、VoC/客服和监管研究预算。
- **副作用：**严格收款门会降低线索数；窄 JTBD 可能不支持 SaaS 规模。
- **最低成本验证：**先做问题访谈和纸面／合成输出评审，不接收投诉原文或账号数据。
- **量化阈值：**≥5 人复现同一高优先 JTBD；≥3 人同意受控影子流程；≥2 家签约且首款到账；每家 ≥1 个输出支持可记录决策。
- **停止／转向：**第 60 天没有两家实付，停止产品建设；转一次性研究服务或结束项目。客户要求身份级原始库时立即拒绝。

#### P11：做 buy/build/manual/no-continuous-collection 同口径 TCO 决策

- **对应根因：**R20、R21、R25、R26。成熟替代众多，官网价格不能反映许可、人工与退出成本。
- **首选方案：**对四个路径用同一 JTBD 和质量门核算 12 个月 TCO：授权厂商／API、客户第一方 VoC、自建受控研究工具、人工抽样或不持续采集；包含许可、回溯、席位、存储、模型、复核、法律、安全、删除、支持和退出。
- **备选与取舍：**若报价不可得，使用区间和“未知”而非单点；优先做人工基线和小型供应商样本回放，不采购长期合同。
- **30／60／90 天：**30 天统一成本字典；60 天取得至少两种替代路径的书面条件或可审计人工基线；90 天结合 P10 的付费与成效作 buy/build/no-go 决定。
- **Owner／能力／依赖：**Owner 为财务／采购与产品负责人共同负责；需要采购、成本建模、退出条款和研究评估；依赖 P02、P06、P10。
- **资源级别：**S 至 M；正式采购暂不批准。
- **地区差异：**大中华区报价常为询价并混合人工服务，须拆信源与值守；欧美按席位、互动量、地点、提及量和数据附加项拆分 [S24]–[S37]。
- **副作用：**严格全成本可能使所有自动化方案暂时无经济性；不同供应商不愿披露来源成本。
- **最低成本验证：**用一个合成问题分别估算 20 小时人工编码、公开套餐上限和自建复核成本，不传真实数据给供应商。
- **量化阈值：**所有路径成本项覆盖 100%；付费覆盖全部直接 API／许可／人工复核成本；影子流程总工时较人工基线下降 ≥30%，盲审质量不下降。
- **停止／转向：**成本高于实付、退出导出不完整或没有重复使用意向时，不自建 SaaS；选择人工／供应商／不持续采集中的最低风险路径。

#### P12：建立双人可接管的责任、运行与事故模型

- **对应根因：**R13、R15、R22、R23、R24、R25。单人维护且身份级结论、导出和事故无人明确负责。
- **首选方案：**定义 RACI：数据权利、法律／伦理、隐私安全、方法、模型、人工复核、导出、事故和最终业务决定分别签字；至少两人能在合成环境重建、停用来源、完成删除和恢复审计。
- **备选与取舍：**团队不足时只保留离线、无真实数据、无 SLA 的研究工具；不假装 24/7 服务。
- **30／60／90 天：**30 天形成 RACI、事件等级和联系方式；60 天用合成 PII 泄漏／错误实体／删除失败做桌面演练；90 天第二名操作者独立完成停用、删除、重建和交接。
- **Owner／能力／依赖：**Owner 为项目责任人；需要研究、隐私、安全、数据工程和客户沟通；依赖 P01、P03、P07、P08、P09。
- **资源级别：**M；对外 SLA 需要 L，当前 no-go。
- **地区差异：**各地区的法律联系人、响应时限和升级机构分开；客户业务决定与研究模型责任不得混为一体。
- **副作用：**双签和人工复核降低速度；小团队可能无法承担，因而必须缩窄范围。
- **最低成本验证：**纯合成环境做一次 90 分钟桌面演练和一次独立接管，不启服务、不接真实数据。
- **量化阈值：**P0 事件在 30 分钟内确认停用决策人；100% 高风险导出双签；至少 2 人完成接管；身份级自动发布为 0。
- **停止／转向：**无法找到第二名合格操作者、事故责任不清或演练无法删除全部派生物时，不承诺对外服务；维持个人离线研究或结束。

### 7. 硬阻断（10 项）

1. **HB01：范围误述。** 任何材料把远端分支／合成测试说成 `master` 已实现或真实验证能力。
2. **HB02：授权未知。** 目标入口或 API 用途、字段、配额、删除、再分发没有书面许可。
3. **HB03：需要规避。** 方案依赖验证码绕过、账号／IP 轮换、隐藏自动化、速率规避或其他违反访问控制／条款的做法。
4. **HB04：批准缺失。** 法律、隐私、伦理、跨境或处理批准未完成、已过期、被撤回或互相冲突。
5. **HB05：PII／保留失败。** 出现一次真实联系方式泄漏、未批准外部模型调用、无法执行保留期或残余识别风险未获批准。
6. **HB06：删除传播失败。** 删除、更正、反对或平台下架未在批准时限传播到任一派生物。
7. **HB07：证据链不完整。** 来源、哈希、规则、schema、依赖、缺失、批准或导出审计存在未知断点。
8. **HB08：质量或偏差不合格。** 代表性／群组／关键类门槛连续两轮失败，缩窄用途后仍不能完成 JTBD。
9. **HB09：高伤害输出失控。** 身份级指控未经人工复核、实体错误合并、投诉陈述被写成事实或出现诽谤事件。
10. **HB10：需求／经济失败。** 第 60 天没有两家签约且首款到账，或第 90 天实付不能覆盖直接许可／API／人工复核成本。

任一硬阻断触发时，对应真实数据来源、模型实验或产品路径立即停止；不得用降低阈值、客户书面接受、删除失败记录、改换账号或扩大抓取来“修复”门禁。
